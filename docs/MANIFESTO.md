# SOBER — build manifesto

How SOBER gets built. Not principles SOBER applies to its users' work; some may later be adopted as product behaviour, but that is a separate decision each time.

## Its relationship to SCOPE

This manifesto shapes **which capabilities belong in MUST**. It does not override `SCOPE.md` rule 1. "Users would find this easier" is an argument for putting something in the MUST list — by ADR, in the open — never a licence to build something that is not in it. A manifesto that could suspend the scope rule would be the same failure v0 had: rules as prose, enforced by nobody.

## User experience over build cost

Users want everything to be easy and effortless. A capability that removes real work from the user is not dropped so the project can finish a week earlier. The number to keep low is the share of users who say "this is too complicated, I am not using it".

## Agent assistance over manual writing

Nobody wants to hand-write decision options or a detailed prompt. The user is an orchestrator: they state what they want and approve what comes back. The agent fills in the rest from what it was given.

The user still owns intent. Drafting is the agent's; picking is the human's.
